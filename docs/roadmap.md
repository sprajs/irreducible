# Roadmap

Irreducible owns the fast compiled physics, numerical methods and shared statistical kernels that connect a declared theory to predicted measurements. Rust owns bounded structural configuration/acquisition/decoding and records; C++20 owns equations and scientific inner loops. Prospector owns source review, compatibility and candidates. Reproducible owns pinned inputs/preparation, external references, experiments/inference/plots and durable S3 evidence. Each shared equation has one compiled owner; observations, source laws, geometry, calibration and selection retain separate identities.

This is the **sole active development plan**, reset on 2026-10-09 from inspected main `179304bcb007a71744bb1882049d9bdef541b88a`. [Gaps](gaps.md) is a factual register with owners/prerequisites/acceptance, not another priority queue. [Capabilities](capabilities.md) and actual source/discovery describe implementation; [scientific contracts](scientific-contracts.md) and specific guides own equations and evidence. The user’s current direction controls scope. Historical plans and unfinished branches supply evidence/custody, never automatic instructions to resume everything.

The next scientific outcome is a faithful fully varied six-parameter source-defined LambdaCDM reference fit using the existing pinned CLASS/official-likelihood bridge. Native full CMB replacement can advance in parallel. The reference is an explicit working model, not truth: source-defined Planck points, a new selected released-likelihood fit, native approximations and later alternatives have distinct identities.

The [dated research review](research-review-2026-10-09.md) records the requested Astra assessment, source snapshots and remaining cross-repository gaps; it is evidence for this plan rather than another work queue.

## Immediate dispatch and bounded native phases

First resolve M0 target/parameter/probe contracts with Prospector and Reproducible, then reproduce and qualify M1 across the admitted LCDM domain. A conditional H0 scan does not satisfy a six-parameter fit. Scope the external numerical sensitivity blocker to the actual admitted fit domain and preserve the failed extension witness.

The native [effective thermal neutrino closure](effective-neutrino.md) supplies
a new explicit total-Neff partition and same-state pressure/acceleration
consumer. It closes that bounded source mapping, while BBN, physical drag,
full-species perturbations and native primary CMB retain their own open gates.

The same retained state now supplies [proper age, direct lookback and particle
horizons](thermal-clocks.md), with a formal fixed-species origin, retained full
early support and independent FD/CLASS clock controls. This observable consumer
does not close changing early thermal content, BBN, drag or perturbations.

In parallel, pick one dependency-ready M3 closure from an accepted consumer discrepancy, not from the number of unfinished branches. A useful native sequence is (a) physical thermal/input/opacity endpoint, (b) regular full-species transfer and amplitude, (c) qualified source/projection/Cl. Existing bounded H/He, acoustic, supplied-source projection and perfect-fluid laws retain their identities. A complete computed raw grid with absent required errors remains refused. Standard physical drag/visibility must not be inferred from a truncated root or renormalized boundary mass.

Select one M4 dataset with actual source, calibrated measurements and identifiable nuisance/selection laws before broadening raw-measurement simulation. Native photometry alone predicts neither intrinsic stellar/SN spectral evolution nor a measured camera response. A named lens needs mass/source/line-of-sight/kinematics; a spherical profile and supplied geometry are prerequisites. Retain this work alongside the baseline, without making every modality a fit prerequisite.

For every package, freeze equations/domain/required outputs and independent acceptance before implementation. Preserve original failures before changing code, references or policy. Benchmark at matched consumer quality, including setup and memory. Keep standalone SDK use, pooled ABI calls and explicit lifetime/factor ownership. Put experiment orchestration and fitting in Reproducible; add a general engine recipe/interface only when a recurring consumer demonstrates the need.
